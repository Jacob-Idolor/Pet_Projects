# Codex project guidance

## Repository scope

- The active application is `radar/`, a static Astro site.
- Run application commands from `radar/` unless a task explicitly concerns the repository root.
- The local release candidate is Jacob Builds: Home, Guides, Resources and About, with three static articles. The owner retired StocksWatch. Read `radar/ARCHITECTURE.md` and the latest section of `radar/LAUNCH_STATUS.md` before continuing.
- Old research/product routes show noindex retirement notices. Jacob Builds is published; the latest verified baseline is main `204f7f175f229fa7514e907c7cd74bb4e6f31db1`. The owner explicitly approved the reviewed reader/SEO polish publication on October 6. Validate the exact release commit and follow required linear-history integration and manual publishing; do not publish unrelated projects or notes.
- `radar/archive/ai-datacenter-screener/` is retained for local and historical reference; it is not deployed.
- `stockswatch.cc` uses Cloudflare Pages. `radar/infra/terraform` defines the Pages project, domain attachment and DNS record; the previous AWS site is recorded as destroyed. Local configuration does not verify live resource state or billing. Active workflows live in the parent repository's `.github/` directory.

## Setup and validation

- Install JavaScript dependencies with `npm ci` (use `npm.cmd ci` in PowerShell if script execution blocks `npm.ps1`).
- Use `npm run dev` for local development.
- For normal code changes, run the narrowest relevant tests plus `npm test` and `npm run typecheck`.
- Run `npm run screener:schema` when screener data or its consumers change.
- Run a build and the Playwright suite for UI, routing, or release-sensitive changes. In PowerShell, set `$env:SCREENER_SKIP='1'; $env:NBIS_SKIP='1'` before an offline build.
- Do not run deploy, infrastructure, alert, email, or live-data mutation commands unless the user explicitly asks.
- On October 6, 2026, the owner explicitly approved the static workflow transition and publication. This revision removes scheduled NBIS refreshes and push-triggered publishing, retains validation jobs, and makes publishing manual. Preserve security, browser and Terraform validation; do not broaden authorization to unrelated merges, infrastructure, credentials, costs or account changes.

## Architecture and editing rules

- Read `radar/ARCHITECTURE.md` before making broad structural changes.
- Keep action-bias calculations centralized in `radar/scripts/lib/action-bias.mjs`; do not duplicate the logic.
- Treat the import order in `radar/src/styles/global.css` as significant.
- Do not hand-edit generated artifacts, including `radar/public/watchlist-board.mjs`, hashed files under `radar/public/datacenter/`, health/settings files, or quote/news/outlook/screener JSON generated by scripts or CI.
- When source changes require generated artifacts, use the matching npm script.

## Security and financial-data safety

- Never commit `.env` files, credentials, API keys, account identifiers, or private market-data entitlements.
- Keep public browser configuration limited to values intentionally prefixed with `PUBLIC_`.
- Preserve the site's "not financial advice" framing. Do not describe scores, signals, forecasts, or backtests as guaranteed outcomes.
- Avoid silently substituting stale or synthetic market data for live data. Make fallbacks and timestamps visible.

## Change discipline

- Preserve unrelated user changes and avoid destructive Git commands.
- Prefer small, focused edits and update documentation when behavior, routes, commands, or configuration change.
- Before handing off a code change, summarize modified files, checks run, and any checks that could not run.
